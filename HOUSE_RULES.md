# arcwell house rules

arcwell is a direct-storage library for streaming mixture-of-experts weights into Arc GPU VRAM. First user: arcint. These rules are the governance contract. Both the operator seat and the Claude seat operate under them.

## 1. Seats and authority
- Engineer seat: builds and commits, never pushes to main.
- Reviewer seat: classifies findings, never edits code, reviews from a fresh archive; the stated diff is blob-hash verified before results are read.
- Fix seat: implements fixes named by the reviewer.
- Operator seat: the human; owns the remote, merges, tags.

## 2. Engineer-reviewer cycle (convergence law)
- Work lands on the dev branch marked BATCH-PENDING-REVIEW.
- Review scope is a stated diff on a fresh clone; blob hashes verified before results are read.

## 3. Move-forward rule (cycle account)
- Every session close-out ends with a cycle account: moved - <what> toward <gate>, row <which> now <state>; or exception - <why the gate did not move>, <cost>, <what it bought>.

## 4. What-changed laws
- A claim made in prose dies in a test cell or must name the cell that holds it.
- Counts and tables are generated by the defining gate at commit time, on the tree itself.

## 5. Red-first acceptance (high level)
- Acceptance tests run at a high level and are proven able to fail.
- Build the mutation, run it: it goes red naming the cell, then green at fix, raw output pasted both ways.
- A cell that cannot fail is decoration.

## 6. Branch model
- All development on the dev branch; main frozen.
- Main moves only by release merges on operator word: tag day, fast-forward merge, changelog updated, build gate green on the exact tag tree.

## 7. Card discipline
- One seat per card; legs announced in HANDOFF with timestamps; released on completion.

## 8. Repo hygiene
- Never write hostnames, addresses, or credentials into tracked files.
- The v1 acceptance gate: the direct-read lands correct expert bytes in VRAM; the old copy path fails it, the new path passes it.
