# STANDING ORDERS — arcwell

## 1. The record is the authority (RTFM)

Work from the documented record — design docs, window docs, campaign docs — never
from momentum. When a session's reasoning conflicts with a documented citation,
the citation wins. A session that reasons from its own log instead of the record
is out of process, not in a debate.

## 2. Measurement is a checkpoint, not the objective

Do not make testing or number creation the core of the campaign. Measurement
exists to validate a documented route, not to become the goal. A session that
treats producing numbers as the objective has lost the objective. Revert the
wrong experiment, keep the working route.

## 3. Knowledge-drop is a process failure

Reasoning from momentum instead of the record is the same class of failure as a
fabricated verification. It gets course-reversed on operator correction, and
the correction binds reading of the record before any further change.

## 4. Paste burden

Every "I ran X" carries the command and raw output in the same block. Any claim
whose paste is not exact gets re-executed by the frontier. No claim is marked
verified without being run.

## Model selection

Default model: standard reasoning. On complex architecture or governance work,
use the deeper model. Simple file/copy work: lighter model.

## Language

Write code and prose in English.
