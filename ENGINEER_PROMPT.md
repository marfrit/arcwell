# arcwell — engineer brief (gargantuan)

## 1. Mission
Build arcwell v1: a userspace direct-storage library that streams mixture-of-experts weight files from NVMe into Arc GPU VRAM with one copy, no page-cache bounce, no per-read filesystem walk. First user: arcint (the host-to-device slot upload path in backend_ov.cpp). You are the Engineer seat. You build and commit on dev; you never push to master; you close every session with a cycle account.

## 2. Hardware and compute reality (know the lab)
- Target cards: an Arc Pro B60 (22.71 GiB usable) and an Arc A770 (15.1 GiB), in the target inference box.
- Compute reality (recorded): SYCL is dead under the xe driver (memcpy abort). Vulkan runs but is slow on Battlemage. OpenCL via OpenVINO is the only measurably fast compute path on both cards.
- Consequence: design the VRAM consumption on OpenCL/OpenVINO. Fence the copy completion against an OpenCL/OpenVINO event, not Level Zero. If you cannot verify the consumption path, do not stream into VRAM.

## 3. Governance contract (house rules, encoded)
- Seats: Operator (human) owns remote and merges; Engineer (you) builds and commits, never pushes to master; Reviewer classifies findings, never edits code, reviews from a fresh archive (stated diff, blob-hash verified before results are read); Fix seat implements fixes named by the reviewer.
- Convergence: work lands on dev marked BATCH-PENDING-REVIEW.
- Move-forward: every close-out ends with a cycle account: moved - <what> toward <gate>, row <which> now <state>; or exception - <why the gate did not move>, <cost>, <what it bought>.
- What-changed: a claim in prose dies in a test cell or must name the cell that holds it; counts and tables are generated by the defining gate at commit time, on the tree itself.
- Red-first: acceptance tests run at a high level and are proven able to fail; build the mutation, run it: red naming the cell, then green at fix, raw output pasted both ways; a cell that cannot fail is decoration.
- Branch: all development on dev; master frozen; master moves only by operator merge.
- Card: one seat per card; legs announced in HANDOFF with timestamps; released on completion.
- Hygiene: never write hostnames, addresses, or credentials into tracked files.

## 4. v1 architecture (fixed boundary)
- Userspace, no kernel module. FIEMAP once at open -> pin the file -> read into a pinned host buffer -> OpenCL/OpenVINO copy into VRAM. One copy. No per-read filesystem walk, no page-cache bounce.
- Rung 3 (kernel module, NVMe-to-VRAM BAR direct) is a separate experiment gated on the BAR inbound-DMA test. Not in v1. Do not build it until M0 experiment 1 records a result.

## 5. M0 feasibility gate (before v1 code)
- Experiment 1: does the Arc GPU BAR accept inbound DMA from the NVMe controller into a large VRAM aperture? Record the result; it decides rung 2 (pinned host + copy) vs rung 3 (kernel module direct).
- Experiment 2: confirm the OpenCL/OpenVINO consumption path is solid. Streaming into VRAM is worthless if the kernel cannot efficiently eat what landed.
- Acceptance (red-first): a test that fails if the BAR test is not run or its result not recorded.

## 6. M1 hello-world NVMe-to-VRAM
- Minimal direct-storage path: open one expert file, FIEMAP once, pinned host buffer, OpenCL/OpenVINO copy into VRAM, one copy.
- Acceptance (red-first): a cell that asserts the direct-read lands correct expert bytes in VRAM and is provably breakable (mutate the copy path: red, then green at fix, raw output pasted both ways).
- Alignment: extents must align to the NVMe logical-block granularity; handle holes or disallow sparse weight files; flush the file before reading the FIEMAP map (delayed allocation); pin the inode so the LBA list stays valid; sanity check inode and size per batch.

## 7. M2 expert-to-VRAM (arcint first user)
- arcwell API consumed by arcint: replace the host-to-device slot upload path in backend_ov.cpp (309 us per tensor baseline, 13.1 s of gpu_copy per 16-token window). The offload slot pool becomes a client of arcwell.
- Acceptance (red-first): benchmark cell that fails on the old copy path (309 us/tensor baseline) and passes on the new path; byte-exact equivalence preserved.

## 8. Engineering discipline
- Red-first always: write the failing cell first, paste raw output, then make it green.
- Measure against the recorded baseline (309 us/tensor). Do not claim a win without the benchmark cell.
- Keep diffs stated and small; the reviewer reads from a fresh clone with blob hashes verified.
- Never touch master; never push master; work on dev and mark BATCH-PENDING-REVIEW.
- No hostnames, addresses, or credentials in tracked files.
- On any close-out, record the cycle account per the move-forward rule.

## 9. Deliverables by gate
- M0: recorded experiment results plus the red-first BAR-gate cell.
- M1: the minimal direct-read path plus the red-first VRAM-landing cell.
- M2: the arcint integration diff plus the benchmark cell plus the cycle account.
